## 1. الملخّص التنفيذي

التطبيق **مكتمل وظيفيًا بدرجة عالية** (35 شاشة، 89 ملف محرّك تصميم، 3 أكواد ECP/ACI/SBC، تصدير PDF/DXF/IFC/CSV، إدارة مشاريع، BOQ، جودة وتنفيذ)، وكوده **منظّم ونظيف بشكل غير معتاد**: لا توجد `TODO/FIXME` متروكة، ولا `GlobalScope`، ولا `runBlocking`، و1,459 استدعاء `stringResource` مقابل 191 نصًا إنجليزيًا مكتوبًا مباشرة في الواجهات، و1,391 اختبارًا وحدة تعمل بنجاح.

لكن هناك **فجوة بين "تطبيق يعمل" و"منتج قابل للنشر والتوسّع التجاري"**. أخطر خمس نتائج (P0) تمنع الإطلاق الآمن اليوم:

| # | النتيجة | الأثر |

```
   → التطبيق يستخدم 3 منها فقط؛ الباقي نسخ مكرّرة من محرّكات app (14 اسم ملف مكرر)

   src/ (Next.js + Prisma + shadcn): نموذج أولي لتحليل الإطارات — غير مرتبط بالتطبيق ولا بالـ CI
```

**نقاط قوة معمارية:** فصل واضح بين الواجهة والمحرّكات، واجهات `base/*` تجعل تبديل الكود مسألة مصنع واحد، مستودعات قاعدة بيانات معزولة، DI بـ Hilt، وحزمة `security/` حقيقية (توقيع + Keystore + Play Integrity).

**نقاط ضعف بنيوية:**
1. **وحدتان للحساب** (`app/domain` + `core`) = مصدر حقيقة مزدوج.
2. `DesignCode` يستورد `android.os.Parcelable` داخل طبقة المجال → يمنع مشاركة المحرّكات مع KMP/خادم/ويب.
3. `CalculatorEngine` (2,438 سطرًا) يكرّر منطق المحرّكات جزئيًا (عزوم/قص/تسليح علوي/تكاليف) بدل تفويض كامل.
4. تطبيق ويب منفصل بلا عقد API مشترك.

## 5. النتائج التفصيلية (بالخطورة والدليل)

### 5.1 خطورة P0 — تمنع الإطلاق التجاري الآمن

**P0-1 — التحقق من الشراء غائب بالكامل**
- الدليل: `billing/BillingManager.kt:32` → `private const val LICENSE_KEY = ""`؛ `grantPremiumAccess()` يكتب `preferencesManager.setPremiumUser(true)`؛ `queryActivePurchases()` يعتمد على استجابة العميل بلا تحقق توقيع ولا Play Developer API.
- الأثر: تفعيل «Pro» بتعديل تفضيلات محلية؛ لا حماية من الاسترداد؛ لا تحقق دوري من صلاحية الاشتراك.
- الإصلاح: تحقق خادمي عبر `purchases.subscriptionsv2.get` (الحد الأدنى: تحقق محلي بالتوقيع `Security.verifyPurchase`) + تخزين الحالة في Keystore/خادم بدل DataStore + إعادة تحقق عند كل إقلاع.

**P0-2 — مزامنة سحابية غير موثوقة تخالف سياسة الخصوصية**
- الدليل: `data/ProjectSyncManager.kt:27` (`BASE_URL = "https://siteengineerpro.com/api/sync"`)، إرسال `POST` لكل التصاميم بلا هيدر مصادقة، بلا إعادة محاولة، بلا معالجة تعارض؛ يُستدعى من `viewmodel/ProjectViewModel.kt:46`. وفي المقابل `play-store/privacy-policy.html:36` ينص أن بيانات التصميم «stored locally … never transmitted to any server».
- الأثر: تعارض صريح بين الإفصاح والسلوك = خطر رفض/تعليق في Play + خطر قانوني (GDPR/PDPL).
- الإصلاح (أسبوع): إمّا تعطيل المزامنة وإزالة الزر، أو تحويلها إلى ميزة opt-in بمصادقة وتشفير + تحديث سياسة الخصوصية ونموذج Data Safety.

**P0-3 — مخاطر فقدان بيانات المستخدم (ترحيلات قاعدة البيانات)**
- ثلاثة أدلة: (1) `db/AppDatabase.kt:73` و`di/AppModule.kt:37` → `.fallbackToDestructiveMigration(true)` مع مسارَي بناء لقاعدة واحدة؛ (2) تحذير بناء فعلي: `w: [ksp] …/AppDatabase.kt:35: Schema export directory was not provided … Room cannot export the schema` رغم `exportSchema = true`، وآخر مخطط محفوظ `app/schemas/…/7.json` فقط بينما الإصدار 12؛ (3) `MigrationTestHelper` = 0 مرجع.
- الأثر: أي تغيير مخطط مستقبلي = مسح صامت لمشاريع المستخدم؛ ولا يمكن التحقق من الترحيلات 8→12 قبل الإصدار.
- الإصلاح: Room Gradle Plugin + `schemaDirectory` + توليد مخططات 8..12 + اختبار ترحيل لكل خطوة + إزالة التراجع التدميري + مسار بناء واحد في Hilt + تصدير/استيراد مشفّر.

**P0-4 — iText 8.0.5 (AGPLv3) في تطبيق مغلق المصدر**
- الدليل: `gradle/libs.versions.toml:21` و`app/build.gradle.kts:245`؛ الاستخدام في 7 ملفات (منها `utils/PdfDrawingGenerator.kt` بـ 3,444 سطرًا).
- الأثر: AGPLv3 تُلزم بإتاحة المصدر أو شراء ترخيص تجاري — خطر قانوني مباشر على منتج تجاري.
- الإصلاح: `android.graphics.pdf.PdfDocument` أو PDFBox-Android (Apache-2.0) خلف واجهة `PdfWriter` مجرّدة (1–2 أسبوع).

**P0-5 — غياب بوابة جودة/CI فعّالة**
- الأدلة: `.github/workflows/android.yml:9` → `workflow_dispatch` فقط (Lint+Tests+Build يدوي)؛ `.github/workflows/gradle.yml` يعمل على push/PR لكنه ينفّذ `assembleDebug` فقط؛ `app/src/androidTest/.../ExampleInstrumentedTest.kt:22` يتحقق من `com.example.civileg2` (حزمة غير موجودة → أول تشغيل على جهاز يفشل)؛ لا تغطية (JaCoCo/Kover) ولا `detekt`/`ktlint`؛ و`./gradlew :app:lintDebug` **يفشل فعليًا** (3 أخطاء، §5.5) فتُرك خطوة Lint في CI بـ `continue-on-error: true`.
- الأثر: 1,391 اختبارًا موجودة لكنها غير محمية من الانحدار.
- الإصلاح: سير عمل واحد على push/PR (Lint + `testDebugUnitTest` + تغطية + `assembleRelease` عند الوسم)، إصلاح/حذف اختبار الجهاز، عتبة تغطية ≥80% للمحرّكات.
